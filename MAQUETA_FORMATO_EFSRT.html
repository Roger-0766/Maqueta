1. Introducción

1.1 Propósito del documento

El presente documento tiene como propósito documentar y describir la Maqueta Web / Prototipo Interactivo del Sistema Web de Gestión Comercial, Pedidos, Inventario y Producción desarrollado para la empresa Confecciones Yamel Sport de la ciudad de Ayacucho, en el marco de la asignatura Experiencias Formativas en Situaciones Reales de Trabajo I (EFSRT I) de la carrera profesional de Ingeniería de Sistemas de Información de la Escuela de Educación Superior Tecnológica Privada La Pontificia.

El prototipo constituye un artefacto complementario a los cuatro (4) documentos base del proyecto: el Estudio de Empresa, el Análisis de Procesos (AS-IS y TO-BE), el Documento de Visión RUP y el Documento de Casos de Uso de Negocio. Permite visualizar de forma tangible la propuesta TO-BE descrita en el Análisis de Procesos y materializa el alcance del MVP definido por el equipo de trabajo.

1.2 Alcance del prototipo

El prototipo implementa una Single Page Application (SPA) interactiva que simula las funcionalidades críticas del sistema, incluyendo:

  • Pantalla de Login con RBAC (Control de Acceso Basado en Roles) con 4 perfiles operativos diferenciados
  • Dashboard Comercial y Gerencial 360° con KPIs e indicadores de gestión
  • Módulo de Clientes con registro y consulta de clientes institucionales, deportivos y particulares
  • Registro de Pedidos TO-BE con matriz dinámica de tallas S, M, L, XL y personalización
  • Cotizador Automático con cálculo de descuentos (0%, 5%, 10%, 15%) y generación de proforma
  • Control de Inventario y Kardex con cálculo automático de Stock Libre (Físico − Reservado)
  • Panel de Producción con cola de pedidos derivados automáticamente desde Ventas
  • Reportes Gerenciales con consolidados de ventas, top de clientes y rotación de insumos
Nota metodológica: El prototipo no constituye la versión final del software productivo. Es una maqueta visual-funcional que permite validar la experiencia de usuario (UX), los flujos operativos y las reglas de negocio simuladas en JavaScript, antes de proceder con la implementación del sistema definitivo.

}

4.3 Restricciones de acceso

Las restricciones se aplican en dos niveles complementarios dentro del prototipo:

  1. Filtrado del menú lateral: cada rol recibe únicamente los ítems de menú que le corresponden, definidos en el objeto USERS.
  2. Control de vistas en el renderizador: la función switchView() valida que la vista solicitada esté dentro del menú del rol activo antes de renderizarla.
const USERS = {
  ventas: {
    nombre: "Karina Quispe",
    rol: "Ventas",
    menu: [
      { id: "dashboard", label: "Dashboard" },
      { id: "pedidos", label: "Pedidos" },
      { id: "cotizaciones", label: "Cotizaciones" },
      // ... más items
    ]
  }
  // ... más roles
};
Beneficio del RBAC: La aplicación de RBAC asegura que cada usuario acceda únicamente a las funcionalidades relacionadas con su rol operativo, reduciendo el riesgo de errores humanos, evitando la exposición innecesaria de información sensible (como montos de dinero a personal de taller) y alineando el sistema con los procedimientos operativos reales de Confecciones Yamel Sport.

5.4 Cotizador Automático

El Cotizador calcula automáticamente el precio final del pedido en base a la siguiente fórmula implementada en JavaScript:

Fórmula de cotización:

Costo de Insumos + Mano de Obra + Sublimado + Margen
    = SUBTOTAL

SUBTOTAL − (SUBTOTAL × Descuento) = TOTAL
TOTAL × 0.5 = Adelanto requerido (RN-01)

9. Conclusiones y Recomendaciones

9.1 Conclusiones

El desarrollo del presente prototipo interactivo ha permitido materializar visual y funcionalmente la propuesta TO-BE del Sistema Web de Gestión Comercial, Pedidos, Inventario y Producción para Confecciones Yamel Sport, cumpliendo con los siguientes logros:

  1. Validación del alcance del MVP: Se implementaron las 8 funcionalidades críticas definidas en el Documento de Visión RUP.
  2. Representación de la matriz RBAC: Los 4 roles operativos fueron correctamente diferenciados, con menús laterales filtrados dinámicamente y restricciones de acceso aplicadas a nivel de vista.
  3. Simulación de reglas de negocio: Las 5 reglas críticas (RN-01 a RN-05) fueron implementadas en JavaScript, demostrando la viabilidad técnica del flujo operativo propuesto.
  4. Aplicación de identidad visual: El diseño Glassmorphism con paleta de rojo deportivo, azul marino profundo y blanco puro, alineado con la identidad de marca de Yamel Sport, generó una interfaz moderna y profesional.
  5. Experiencia de usuario validada: El prototipo resultó intuitivo para los usuarios de prueba, con flujos claros y navegación SPA sin recargas de página.

9.2 Recomendaciones para la siguiente fase

  • Persistencia en base de datos: Migrar el estado en memoria a un backend con base de datos relacional (PostgreSQL o MySQL).
  • Autenticación real: Implementar autenticación JWT con roles persistentes en lugar de la selección de perfil de prueba.
  • Integración con WhatsApp Business API: Conectar el módulo de cotización con la API oficial de WhatsApp para envío automático de proformas.
  • Módulo de reportes avanzado: Incorporar gráficos interactivos con Chart.js o D3.js.
  • Pruebas de usabilidad con usuarios reales: Validar el prototipo con la propietaria y los encargados de cada área.
  • Optimización mobile-first: Reforzar la experiencia en dispositivos móviles, considerando el uso mayoritario de WhatsApp como canal comercial.
Conclusión final: El prototipo interactivo constituye una herramienta estratégica de comunicación y validación, que traduce los artefactos técnicos (Estudio de Empresa, Análisis de Procesos, Visión RUP y Casos de Uso de Negocio) en una experiencia visual tangible, facilitando la alineación de expectativas entre el equipo de desarrollo, la propietaria y los usuarios finales de Confecciones Yamel Sport.
